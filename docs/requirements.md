# 共有Todoリストアプリ 要件定義

作成日: 2026-08-01

## コンセプト

Google Keep 代替の、URL共有型・複数人利用のTodoリストアプリ。買い物リスト用途を主シナリオとする。Cloudflare 上に構築する。
主シナリオは「家族数人での買い物」: スーパーで誰かがカゴに入れてチェックすると、他の人の画面にも即座に反映される。

## 機能要件

### アカウント / 認証

- リスト**作成者のみ**アカウントが必要。認証は**パスキー（WebAuthn）のみ**。OAuth・パスワードは使わない
- 1アカウントで**複数リストを作成可能**（「日用品」「実家用」など）

### 共有 / 権限

- リストごとに**推測不能なランダムトークン入りURL**を発行（例: `/l/<長いランダムID>`）。LINE 等で URL を送れば誰でも参加できる
- URLアクセス者（匿名・認証不要）: 項目の追加・編集・削除・チェックON/OFF **すべて可能（フルアクセス）**
- **作成者のみ**できる操作:
  - リスト自体の削除
  - Undo（過去世代への復元）

### 世代管理 / 履歴

- すべての変更を履歴として記録（いつ・どの操作か）
- 匿名ユーザーは**端末ごとに自動生成した識別子**で区別し、任意でニックネームを設定できる（初回入力の強制はしない — URLを開いてすぐ使える手軽さを優先）
- 作成者は履歴を見て**任意の過去世代に復元（Undo）**できる
- MCP（AI）経由の変更は「AI経由」として履歴に記録する

### リアルタイム同期（必須）

- 同じリストを開いている全員に変更が即時反映される
- 同時アクセスは**最大10人程度**の想定
- **1リスト = 1 Durable Object** に WebSocket 接続を束ねる構成（Hibernation API でコスト最小化）
- MCP 経由の変更も同じ Durable Object を通じてブロードキャストする

### UX要件（Google Keep 風）

- **項目追加はテキスト入力ベース**: 入力欄に打って Enter で即追加。モーダルや画面遷移なし
- **1項目 = 1チェックボックス付き行**: タップで ON/OFF 切り替え
- **チェック済み項目は下部にまとめて表示**（Keep と同じ挙動）
- **モバイルファースト**: スマホでの買い物中の操作性を最優先

### MCP連携

- Worker 上に MCP エンドポイント（`/api/mcp`、http transport）を実装し、Claude Code などの AI クライアントからTodoリストを操作可能にする
- 認証: 作成者アカウントに紐づく API トークン（Bearer）。lifestyle MCP と同じ方式で `~/.claude.json` に登録して使う。トークンは設定ファイル以外（コード・ドキュメント・会話）に書かない
- 提供ツール（案）:
  - `list_todo_lists` — 自分のリスト一覧
  - `get_items` — リストの項目取得（チェック状態含む）
  - `add_items` — 項目追加（複数一括対応。「カレーの材料を追加して」用途）
  - `update_item` / `delete_item` — 編集・削除
  - `check_item` / `uncheck_item` — チェック操作

## スコープ外（今回はやらない）

- Google Keep からのデータ移行（新規で使い始める）
- 細かい権限管理（閲覧専用リンク等）— 必要になったら後で追加

## 技術スタック（lifestyle-app 踏襲 + 差分）

- Hono + Cloudflare Workers + **D1**（リスト・項目・履歴・認証情報の永続化）
- **Durable Objects**（リアルタイム同期。lifestyle-app には無い新規要素）
- React + Vite フロントエンド
- pnpm workspaces モノレポ
- パスキー: `@simplewebauthn/server` / `@simplewebauthn/browser` を想定

## 想定データモデル（次フェーズで詳細設計）

- `users` — 作成者アカウント
- `credentials` — パスキー資格情報（1ユーザー複数可）
- `api_tokens` — MCP 用 Bearer トークン
- `lists` — リスト（共有トークン、作成者、タイトル）
- `items` — 項目（テキスト、チェック状態、並び順）
- `revisions` — 世代管理・変更履歴（操作種別、操作者識別子、スナップショットまたは差分）
